01 · Overview

Two parts, one GPU

Where it lives

  • Both parts are in the VICKY I/O block $FC. Map that block into any 8 KB slot of the task; FS2 maps it at $6000, so there the SceneEngine is $7780 and the Renderer $7800.
  • The point port sits at the fixed I/O addresses $FED8-$FEDF, always visible.
  • GPU_ID (Renderer +$1F) reads $34; a core without the GPU reads $FF.

Three ways to draw

  • Records Renderer — the CPU writes 8-byte units to the record window: 2D lines and fills, screen-space polygons, SWAP.
  • Resident meshes Renderer — vertices and faces uploaded once; per object per frame the CPU sends SETMAT and MESH and the mesh unit transforms, lights, clips and draws every face.
  • Display lists SceneEngine — the walker runs a scenery list from its own RAM and, with SEPORT on, sends its polygons, lines and lights straight to the Renderer.

04 · Both

Coordinates, projection and the depth key

Projection (meshes, SETPROJ)

X16 = CX + FX × x / z        (sixteenths of a 640 dot)
Y16 = CY - FY × y / z        (sixteenths of a row)
key = f16( NEAR × 2^28 / z )  (16-bit depth key)
z clipped at NEAR >> shift, x and y to a guard band
(-16384 .. 26624 sixteenths) before the divide
The SceneEngine projects with its own view registers
(center, scale, largest: SceneEngine +$B/+$C).

The depth key

A 16-bit float of 1/z: a 4-bit exponent and a 12-bit mantissa, so depth resolution is 1/4,096 of the distance at every range. Larger is nearer; the buffer clears to 0 (farthest); $FFFF is the near plane. A dot is drawn when its key is at least the stored key (equal passes).

q < 2^14 :  key = q / 4
otherwise:  p = bit length(q) - 1          (14..27)
            key = (p - 13) << 12  |  12 bits under q's top bit
05 · Renderer

Resident meshes

Drawing a mesh

  1. Upload faces and vertices once (target 1). A face's indices count from the MESH record's vertex base.
  2. SETPROJ and SETLIGHT once (they stay until changed).
  3. Per object, per frame: SETMAT, then MESH (first face, count, vertex base, material override). The mesh unit transforms, lights, clips at the near plane and the guard band, projects and draws every face.

The arithmetic

view   = ((M × p) << scale) >> 7  +  T
N_view = M × n                           (Q15)
shade  = amb + dif × max(0, N_view · L) >> 15
         clamped 0-255; flat faces use the face
         normal, GOURAUD the vertex normals

View space: x right, y up, z forward (in front of the eye is z > 0). Faces are drawn whichever way they wind unless CULL is set.

06 · Renderer

Shading and the shade LUT

  • DIRECT skips the LUT: the material (or texel) is the color index itself.
  • SCREENDOOR draws every other dot: see-through without blending (the colors are indexed, so there is no alpha).
  • Switching MODE at run time needs both LUT tiles filled; MODE is latched at SWAP.
07 · Renderer

Textures

What a texel is

  • Texture memory is 256 KB (upload target 0), 8-bit texels, row-major from the base: texel (u, v) is at base + v × width + u.
  • A texel is a material: it goes through the shade LUT at the face's light level, so a texture shades with the surface. With DIRECT it is the color index.
  • Texel 0 is transparent: nothing is drawn there. A texture meant to cover its face holds no 0.
  • Room for 64 textures of 64×64, 16 of 128×128 or 4 of 256×256.

Putting one on a face

  1. Upload the texels (target 0) and the descriptor (target 3).
  2. Set TEXEN (GPU_CTRL b6).
  3. Mesh face: flags | $08, byte 7 = texture id. POLY: flags | $08, header byte 2 = id, then the UV units.
  4. Give each vertex u, v in texels, 8.8 (u = 64.0 is $4000).

Sampling is nearest, perspective-correct at every 16th dot and linear between; each axis wraps or clamps per the descriptor. TexConv turns a PNG into texels of a material set, with the descriptor and upload chunks ready.

08 · Renderer

Distance haze

if HAZE_CTRL.b0 and 0 < key < HAZE_START:
    h = min(16, (HAZE_START - key) × HAZE_SCALE >> 16)
    the dot takes HAZE_COLOR when h > Bayer4×4(dot)

Farther than HAZE_START (a smaller key) the haze color dissolves in through an ordered 4×4 pattern, completely at h = 16. Set HAZE_COLOR to the sky color each frame so the far scenery fades into the horizon.

10 · Renderer

A frame

* setup, once
        lda   #$10
        sta   GPU+$00          RESET
        lda   #164
        sta   GPU+$07          VIEW_ROWS
        ...                    uploads: LUT, meshes, textures
        lda   #%01100111       TEXEN AUTOCLEAR ZEN MODE=320 EN
        sta   GPU+$00

* push the 8-byte unit at X (FIFO room checked first)
Push    ldd   GPU+$02          FIFO_FREE (+$02 latches +$03)
        beq   Push
        ldd   ,x
        std   GPU+$40
        ldd   2,x
        std   GPU+$42
        ldd   4,x
        std   GPU+$44
        ldd   6,x
        std   GPU+$46          byte 7 (the tag) pushes
        leax  8,x
        rts

Per frame

  1. Background: HSPLIT for sky and ground, or let AUTOCLEAR clear to CLEAR_COLOR.
  2. Scenery: start a SceneEngine run (SEPORT on), or send POLY records.
  3. Objects: SETMAT + MESH each.
  4. SWAP. The flip waits for everything ahead and for the raster to leave the view rows.
  5. Stay at most one frame ahead: before the SWAP of frame n + 2, wait until SWAP_COUNT reaches n (or take the interrupt).

MODE is latched at SWAP, so a program can change mode between frames.

Memory

  • $0000-$1FFF variable RAM (8 KB): the program's variables the list reads and writes; written-back changes come out of OUT.
  • $4000-$7FFF scene RAM (16 KB): display lists and their data.
  • Upload and read back through ADDR / +6, only while the walker is not busy.

Display-list ops for textures

  • $36 tt TEX: polygons from here on take texture tt.
  • $37 NOTEX: untextured again.
  • $38 uuuu vvvv UV: the texture coordinates of the vertices that follow; clipped vertices get interpolated u, v.
  • GO and GO-AT start untextured.

With SEPORT on (GPU_CTRL b7)

The walker's drawing goes straight to the Renderer, not to OUT:

  • VTX: a projected vertex (X16, Y16, depth key; u, v when textured); up to 32 make a polygon.
  • FILL: draws the vertices as one polygon in a DIRECT color. Buildings are depth-tested and written; ground decals (pavement, markings) are neither, in list order.
  • LINE3: a 3D line as a one-dot quad, depth-tested with its ends' keys.
  • DOT: a light, one 320-dot by one row, depth-tested.
  • SLINE: a screen line, no depth.

Row positions are scaled by SE_YMUL on the way (Renderer +$0E).

The point port, $FED8-$FEDF

AddressWriteRead
$FED8a ground point's words (x, z)a result word (pops)

The port runs on the SceneEngine's own transform and projection units, between list runs: a transformed point gives its camera words (and its exponent and flags), a projected one gives X16, Y16 and the view units. It answers within a few clocks of the point's last word.

13 · Both

The GPU interrupt

A 64-clock pulse into VICKY's interrupt input bit 2, which is the interrupt controller's bit 9 (group 1, bit 1), masked at reset. It fires when:

  • a SceneEngine run stops (END, a CPU op, a fault), or
  • the Renderer's SWAP_COUNT or FENCE_COUNT moves.

Use it in place of polling STATUS or SWAP_COUNT. Read the counters in the handler to tell which event it was.

14 · Both

Limits and gotchas

Sizes

  • Frame: 640×240 at 16 colors or 320×240 at 256, two buffers, 16-bit depth per 640 dot.
  • Mesh RAM: 4,096 entries (faces and vertices share them).
  • Textures: 256 KB; 256 descriptors; sizes 8-256.
  • Shade LUT: 256 materials × 32 levels, one tile per mode.
  • POLY: 3-8 vertices. Record FIFO: 512 units.
  • SceneEngine: 8 KB variables, 16 KB scene, 32 vertices a polygon.

Gotchas

  • Texel 0 is a hole, not black.
  • Uploads only while the Renderer is IDLE; SceneEngine uploads only while it is not busy.
  • A record cut short, or a CONT with no record open, sets BADREC; an index past entry 4,095 sets MESHERR. Both stay set until written 1.
  • AUTOCLEAR clears only the view rows (VIEW_ROW0, VIEW_ROWS).
  • Equal depth keys pass the test: draw a decal after its surface, with ZTEST and no ZWRITE.
  • LINE and SPAN coordinates are whole 640 dots and rows; polygons are in sixteenths.

Values on this page are taken from the GPU's reference model, which its hardware matches bit for bit.
